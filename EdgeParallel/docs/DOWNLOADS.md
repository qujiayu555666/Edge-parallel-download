# 下载机制与故障排查

## 接管流程

扩展等待 Edge 确定完整文件名，并确认原请求符合条件。随后暂停原任务，由助手检查服务器分段能力、大小及文件版本，再建立加速任务。只有 Edge 接受加速任务后才取消原任务；准备或取消失败时尝试恢复原任务。

助手通过多个 HTTP Range 请求读取同一文件，检查各段的 `206` 状态、`Content-Range`、字节数及文件版本，再按顺序传给 Edge。Edge 负责写文件和显示下载进度。扩展不能修改 Edge 内部下载引擎。

下载核心延续 0.1.3 的实现：分片大小在 256 KiB–2 MiB 之间按文件大小和连接数选择；同一文件的多个浏览器请求共享连接上限。响应头等待与读取停顿分别计时，失败分片可以重试。0.2.0 主要更新安装与面板体验。

## 支持范围

自动接管需要公开 HTTP/HTTPS 地址、无认证的 GET 请求、确定的文件大小，以及可验证的 ETag 或 Last-Modified。浏览器响应与助手探测到的大小和版本必须一致。

以下情况继续使用 Edge 原生下载：

- Cookie、Authorization、已有续传头，或 POST 表单请求。
- `blob:`、`data:`、隐私窗口、其他扩展发起的任务或直接本地网络地址。
- 未知文件长度、压缩响应、不支持 Range、版本标识不可靠，或内容随请求头变化。
- 浏览器缓存使原请求信息不完整，或同一 URL 的并发请求无法唯一关联。

一次性链接、防盗链和限制客户端的网站也可能无法接管。面板中的直链入口可以直接建立公开文件任务，但不能代替登录认证，也不能保证受限链接可用。

## 文件名与临时文件

组件根据服务器文件名、Edge 的目标名称和链接确定文件名，保留中文及 `.exe`、`.zip`、`.tar.gz` 等后缀；无法确定时不凭空猜测。加速任务使用 Edge 默认下载目录，同名文件自动加序号。

Edge 可能使用 `未确认 … .crdownload` 等随机临时名称。能否找到“最终文件名 + .crdownload”不是接管条件。

对能准确记录的原任务临时文件，组件在加速任务完成后重新检查文件和目录身份，再执行清理；文件占用时会有限重试。随机临时文件由 Edge 取消原任务时处理。组件不会扫描目录猜测归属，移除取消记录也不等于确认未知文件已经从磁盘删除。

旧版留下的无后缀文件和无法追溯任务的临时文件不会被批量修改。清理未知遗留文件前，请先确认没有其他下载仍在使用它。

## 常见问题

**显示已连接，但没有加速。** “已连接”表示助手可用。查看面板中最近一次接管结果；活动任务会显示正在加速，扩展图标显示数量。可以用一个无需登录、支持 Range 的大文件进行检查。

**连接更多却没有更快。** 连接选项是上限。服务器可能按 IP 限速，额外连接还可能增加等待与重试。面板速率按近期收到并验证的分片估算，可能短时跳动；不要仅用瞬时峰值比较下载器。

**无法连接助手。** 等下载结束后重新运行安装器，确认 Edge 加载的是向导提供的新目录，再重新加载扩展。若从旧目录迁移，移除旧扩展后加载新目录；移除扩展可能清除设置。

**更新后仍显示旧版本。** 先等下载结束，再在 `edge://extensions` 重新加载扩展。不要删除正在使用的安装目录。旧版保存在 `EdgeCore` 中时，应按 README 的迁移步骤切换到当前用户安装目录。

**下载中断。** 同一浏览器与助手会话中的暂时网络中断可在 Edge 下载列表尝试继续。关闭 Edge、重新加载扩展或结束助手后，旧的本地链接可能失效，需要从原网站重新下载。

## 反馈问题

提交 Issue 时可提供 Windows/Edge 版本、扩展和助手版本、面板原文、连接设置及可公开分享的复现链接。说明问题出现在自动接管还是直链下载。不要公开 Cookie、认证头、私有下载链接或个人目录信息。
